# cookies_exporter.py — أداة استخراج كوكيز المتصفح

سكربت Python لاستخراج كوكيز المتصفح إلى ملف `cookies.txt` بصيغة **Netscape** الصالحة
لـ `yt-dlp` (وكذلك `curl` و`wget`)، يعمل على **لينكس وويندوز وماك (macOS)**.

الفكرة: المتصفح (Chrome/Firefox/…) يملك الجلسة مسجّلة، لكن `yt-dlp` لا يستطيع قراءة
قاعدة بيانات المتصفح المشفّرة. هذا السكربت يفكّ التشفير عبر `yt-dlp` نفسه ويكتب النتيجة
في ملف قياسي، مع **تحقق** من أن الملف صالح فعلاً قبل استخدامه.

---

## 1) المتطلبات

```bash
pip install -U yt-dlp
```

| النظام | ما يلزم إضافياً |
|---|---|
| **Windows** | لا شيء — يتم فك التشفير عبر DPAPI تلقائياً. |
| **macOS** | لا شيء — يتم فك التشفير عبر Keychain (قد يظهر طلب إذن مرة واحدة). |
| **Linux + Firefox** | لا شيء. |
| **Linux + Chrome/Chromium/Edge/Brave** | `pip install secretstorage` (يتطلّب `libsecret-1`) — أو استخدم Firefox. |

```bash
# Ubuntu / Debian
sudo apt install -y libsecret-1-0
pip install secretstorage
```

> بدون `secretstorage` على لينكس، يفشل فك تشفير كوكيز Chromium ويظهر:
> `Failed to decrypt with DPAPI` أو `could not find Chrome cookies database`.

---

## 2) التشغيل السريع

```bash
python cookies_exporter.py
```

ما يفعله تلقائياً:

1. يفحص كل المتصفحات المثبّتة ويعرض عدد الكوكيز لكل منها.
2. يختار المتصفح الذي يحتوي جلسة **مسجّلة** (يحتوي `LOGIN_INFO` + `SAPISID`).
3. يكتب `cookies.txt` في المجلد الحالي (نسخة احتياطية `cookies.txt.bak` إن وُجد ملف سابق).
4. يفحص الملف (فحص ثابت + فحص حي عبر الشبكة).
5. يطبع الأمر الجاهز للاستخدام مع `yt-dlp`.

## 3) الخيارات

```
-b, --browser    {auto,chrome,chromium,edge,brave,opera,vivaldi,whale,firefox,safari}
                 المتصفح المصدر (default: auto)
-p, --profile    اسم ملف التعريف أو مساره   (مثال: Default)
    --keyring    {kwallet,basic,gnome}       خزنة المفاتيح في لينكس
    --container  حاوية فايرفوكس (container id)
-d, --domain    نطاق مطلوب (يمكن تكراره)      default: youtube.com, google.com
-o, --output    مسار ملف الإخراج               default: cookies.txt
    --all-domains   تصدير كل النطاقات (بدون فلترة)
    --json FILE     نسخة JSON إضافية
    --no-backup     عدم حفظ نسخة احتياطية
    --no-verify     تخطّي التحقق
    --no-live       تخطّي التحقق الحي (لا يحتاج إنترنت)
    --verify FILE   فحص ملف موجود فقط ثم الخروج
    --test          بعد التصدير: تشغيل yt-dlp لاختبار فعلي
-u, --url       الرابط المستخدم في الاختبار الفعلي
    --list         عرض المتصفحات المتاحة ثم الخروج
-v, --verbose   تفاصيل إضافية
```

### أمثلة

```bash
# تصدير من Chrome إلى مسار محدّد
python cookies_exporter.py -b chrome -o ~/cookies.txt

# فايرفوكس بملف تعريف محدّد
python cookies_exporter.py -b firefox -p default

# كل نطاقات المتصفح (مثلاً لمواقع أخرى)
python cookies_exporter.py -b chrome --all-domains

# فحص ملف قديم
python cookies_exporter.py --verify ~/cookies.txt

# تصدير + اختبار تنزيل حقيقي
python cookies_exporter.py --test -u "https://youtu.be/VIDEO_ID"

# على لينكس مع kwallet
python cookies_exporter.py -b chrome --keyring kwallet
```

## 4) صيغة الملف الناتج

صيغة Netscape القياسية (7 حقول مفصولة بـ Tab):

```
# Netscape HTTP Cookie File
# This file is generated by cookies_exporter.py. Do not edit.
# Exported: 2026-10-21 14:43:00 CET
# Cookies: 92

.youtube.com	TRUE	/	TRUE	1790123456	LOGIN_INFO	...
.youtube.com	TRUE	/	TRUE	1790123456	SAPISID	...
```

| العمود | المعنى |
|---|---|
| 1 | النطاق (`domain`) |
| 2 | `TRUE` إذا شمل النطاقات الفرعية |
| 3 | المسار |
| 4 | `TRUE` لكوكي `secure` (HTTPS فقط) |
| 5 | تاريخ الانتهاء (Unix timestamp) — `0` لكوكي الجلسة |
| 6 | اسم الكوكي |
| 7 | القيمة |

**تفاصيل مهمّة يطبّقها السكربت:**

* **تحويل تاريخ الانتهاء**: Chrome يخزّن `expires_utc` بالميكروثواني منذ 1601-01-01،
  و yt-dlp يمرّرها كما هي. السكربت يحوّلها إلى ثواني منذ 1970:
  `expires = expires / 1_000_000 - 11644473600`.
* **كوكي الجلسة** تُكتب بقيمة `0` في عمود الانتهاء.
* **تنظيف القيم**: تُستبدل المسافات البادئة (Tab) والأسطر الجديدة بمسافة حتى لا يتكسر
  الملف (وإلا رفضه `yt-dlp` بخطأ `invalid expires`).
* **لا دمج أبداً**: الملف يُكتب كاملاً من الصفر. الدمج مع كوكيز قديمة يُبطل الجلسة.

## 5) ماذا يفعل التحقق؟

### الفحص الثابت (بدون إنترنت)

يطبّق نفس قاعدة `yt-dlp` في `extractor/youtube/_base.py`:

* يجب وجود `LOGIN_INFO`، وإلا يعتبر `yt-dlp` الجلسة غير مسجّلة ويظهر:
  `Sign in to confirm your age`.
* يجب وجود واحد على الأقل من `SAPISID` / `__Secure-1PAPISID` / `__Secure-3PAPISID`
  (وإلا تعذّر حساب `SAPISIDHASH` الذي يوقّع الطلبات).
* تحذير عند وجود كوكيز منتهية الصلاحية أو كوكيز VID ناقصة.

### الفحص الحي (يحتاج إنترنت)

يرسل الكوكيز فعلياً إلى `https://www.youtube.com/` ويبحث عن
`"LOGGED_IN":true` داخل `ytcfg`. هذه هي الطريقة الوحيدة للتأكد من أن الجلسة حيّة
فعلاً (الكوكي موجود في الملف ≠ الكوكي مقبول من يوتيوب).

### الاختبار الفعلي (`--test`)

يشغّل `yt-dlp --cookies <file> --simulate` للتأكد من أن الملف يعمل مع يوتيوب فعلياً.

## 6) استخدام الملف مع yt-dlp

```bash
# تنزيل فيديو بجودة عالية مع الكوكيز
yt-dlp --cookies cookies.txt -f "bv*+ba/b" --merge-output-format mp4 "https://youtu.be/VIDEO_ID"

# أو بدون ملف: اقرأ من المتصفح مباشرة (كوكيز طازجة دائماً)
yt-dlp --cookies-from-browser chrome -f "bv*+ba/b" "https://youtu.be/VIDEO_ID"
```

## 7) تحذيرات مهمة (دروس من التجربة)

1. **يوتيوب يُدوّر (rotates) الكوكيز.**
   بعد كل استخدام، ترسل يوتيوب `Set-Cookie` جديدة (`__Secure-1PSIDTS`, `SIDCC`, `PREF` …)
   وأحياناً تحذف كوكيز الجلسة بـ `Max-Age=0`. `yt-dlp` يحفظ الحالة الجديدة في نفس
   الملف عند انتهاء التشغيل، وأحياناً تُحذف كوكيز المصادقة (`LOGIN_INFO`, `SAPISID` …)
   من الملف نتيجةً — فيصبح الملف معطوباً ويظهر:
   `The provided YouTube account cookies are no longer valid.`

   **الحل**: أعد التصدير قبل كل جلسة تنزيل، أو استخدم `--cookies-from-browser`.
   السكربت `yt.py` في هذا المجلد يفعل ذلك تلقائياً (يصدّر كوكيز جديدة قبل كل تشغيل).

2. **لا تدمج ملفين.** دمج كوكيز قديمة مع حديثة (أو تمرير `--cookies-from-browser`
   مع `--cookies` لملف قديم) يجعل الكوكيز القديمة تتغلّب على الحديثة ويُفشل الطلب.

3. **الملف حسّاس.** `cookies.txt` يعادل تسجيل دخول كامل لحسابك.
   لا ترفعه إلى git ولا تشاركه، واحذفه بعد الانتهاء:
   ```bash
   shred -u cookies.txt      # أو: rm -f cookies.txt
   ```

4. **المتصفح يجب أن يكون مفتوحاً ومحلياً.** يوتيوب قد يطلب من المتصفح تسجيل دخول
   جديد (CAPTCHA أو "Confirm you're not a bot") — نفّذها من المتصفح ثم أعد التصدير.

## 9) بيئة التشغيل: `.venv` + مزوّد PO Token

كل شيء يعمل داخل `.venv` الموجود في مجلد المشروع:

```bash
cd /home/xq/test_download
./.venv/bin/python cookies_exporter.py      # تصدير الكوكيز
./.venv/bin/python yt.py                    # تنزيل
```

| المكوّن | الموقع | ملاحظة |
|---|---|---|
| yt-dlp + الإضافات | `.venv/lib/python3.13/site-packages` | `yt-dlp 2026.08.19` + `bgutil_ytdlp_pot_provider 2.0.2` |
| خادم PO Token | `bgutil-ytdlp-pot-provider/server` (داخل المشروع) | `build/main.js` جاهز، يعمل على المنفذ `4416` |
| مزوّد HTTP | `http://127.0.0.1:4416` | مسجّل كخدمة مستخدم |
| مزوّد السكربت | `bgutil-ytdlp-pot-provider/server` | بديل عند تعطّل الخادم |
| node / deno | `~/.local/node22/bin/node`، `~/.local/bin/deno` | node ≥ 22 لتحديات JS |

### خدمة PO Token (systemd --user)

```
~/.config/systemd/user/bgutil-pot.service
```

```bash
systemctl --user status  bgutil-pot.service   # الحالة
systemctl --user restart bgutil-pot.service   # إعادة التشغيل
curl -s http://127.0.0.1:4416/ping            # فحص سريع (يجب أن يردّ 200)
```

الخدمة تعمل من نسخة المشروع المحلية (`WorkingDirectory=.../test_download/bgutil-ytdlp-pot-provider/server`).

### فخ مهم في `extractor_args` (عبر Python API)

قيم `extractor_args` يجب أن تكون **قوائم نصوص**، وإلا تعاملها yt-dlp كمحارف مفردة:

```python
# ✔ صحيح
"extractor_args": {"youtubepot-bgutilhttp": {"base_url": ["http://127.0.0.1:4416"]}}

# ✘ خطأ: يمرَّر النص حرفاً بحرف فيصير الرابط "h" وتظهر رسالة
#   Unsupported url scheme: ''
"extractor_args": {"youtubepot-bgutilhttp": {"base_url": "http://127.0.0.1:4416"}}
```

عند سطر الأوامر لا مشكلة (yt-dlp يحوّلها لقائمة تلقائياً):
```bash
yt-dlp --extractor-args "youtubepot-bgutilhttp:base_url=http://127.0.0.1:4416" ...
```

## 10) أسئلة شائعة

**هل يعمل على ويندوز/ماك؟**
نعم — منطق الملف واحد، وتُبنى مسارات المتصفح داخلياً حسب النظام
(`%LOCALAPPDATA%` في ويندوز، `~/Library/Application Support` في ماك،
`~/.config` في لينكس). فك التشفير يتم عبر `yt-dlp` (DPAPI / Keychain / libsecret).

**ظهر خطأ `could not find chrome cookies database`؟**
المتصفح غير مثبّت أو لا توجد قاعدة كوكيز (لم تسجّل دخول أي موقع بعد).

**ظهر خطأ `Failed to decrypt with DPAPI` على لينكس؟**
ثبّت `secretstorage`: `pip install secretstorage` و`sudo apt install libsecret-1-0`.

**الملف أُنتج لكن يوتيوب ما زال يقول "Sign in to confirm your age"؟**
الفيديو مقيد بالعمر ويتطلّب **PO Token**. راجع القسم 9 (مزوّد bgutil + `js_runtimes` deno/node).

**ظهر خطأ `Unsupported url scheme: ''` أو `web_creator client https formats require a GVS PO Token`؟**
قيمة `base_url` في `extractor_args` ليست قائمة نصوص — انظر الفخ المهم أعلاه.
أو أن خادم PO Token متوقّف: `systemctl --user restart bgutil-pot.service`.

**هل يمكن استخدامه لمواقع غير يوتيوب؟**
نعم — `--all-domains`، أو `-d example.com` لتحديد نطاق. التحقق الحي مخصّص ليوتيوب،
أمّا الفحص الثابت فيصلح لأي ملف Netscape.

**كيف أفحص ملفاً بدون استخراج جديد؟**
`python cookies_exporter.py --verify path/to/cookies.txt`
